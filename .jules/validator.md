## 2024-05-28 - Missing module import in dynamically loaded scripts

Coverage Gap: tests/test_screenshot.py dynamically loads `deployment/screenshot.py` via `importlib.util.spec_from_file_location('screenshot', path)`. However, `screenshot.py` attempts to import `config` locally (e.g., `from config import ROOT`), which fails because the module is being loaded outside of standard package resolution boundaries when executed via `spec.loader.exec_module()`. The import error prevents multiple tests from executing correctly.
Learning: When using `importlib.util.spec_from_file_location` to test standalone scripts that rely on local relative imports, the script's directory might not be in `sys.path`, leading to `ModuleNotFoundError` during module execution. In Python, modifying `sys.path` within the test before loading the module allows relative imports like `from config import ROOT` to resolve properly.
Assertion: Inject the target script's parent directory into `sys.path` dynamically before calling `spec.loader.exec_module()`, and ensure it's removed afterward to prevent polluting the test environment's import resolution paths.
Learning: When loading dynamic modules with `spec_from_file_location`, the module name passed to `pytest --cov=` or the internal `sys.modules` name must exactly match what coverage expects. If coverage warns `Module deployment/screenshot.py was never imported`, it indicates the name given to `spec_from_file_location` (`'screenshot'`) does not match the file path being measured by pytest-cov.
Assertion: Ensure that when dynamically loading a script via `importlib`, you pass a module name that aligns with its path (e.g. `deployment.screenshot`), so that pytest-cov successfully tracks execution against the specified source file.
