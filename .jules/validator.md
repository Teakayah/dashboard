## 2026-11-08 - Fix Flaky Timeout in `test_viz_elements_have_height`
Coverage Gap: `test_viz_elements_have_height` in `tests/test_usability.py` occasionally fails with a timeout while waiting for `wait_for_function` to return `true` on visualization elements having a height.
Learning: The test flakiness is due to Playwright's `TimeoutError`. The current `wait_for_function` checks if *any* `canvas` or `map` has `offsetParent !== null` and `offsetHeight < 10`. If they *all* have a height >= 10, it returns `true`. However, for some tabs, or due to slow rendering (like when loading Chart.js or DuckDB-wasm in `dropzone.html` or Map components in `flood_risk_gatineau_ottawa.html`), the canvases might take longer to load and receive their dimensions. A `timeout=15000` is used, but it can still timeout if the elements remain small or `offsetParent` is unexpectedly truthy without a height yet. We can catch the TimeoutError specifically to avoid silently swallowing real errors.
Assertion: When handling expected timeouts in Playwright, explicitly import and catch `TimeoutError as PlaywrightTimeoutError` from `playwright.sync_api` to ensure actual connection or execution errors are not suppressed. Also, the wait condition should check if the canvases actually exist or let the test run correctly.
